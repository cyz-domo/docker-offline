# Docker Offline Builder SaaS 控制台界面设计

## 目标

将现有 Worker 内嵌页面优化为简洁的 SaaS 控制台风格，重点提升构建任务的可见性、进度反馈和历史任务浏览体验。改版不改变现有 GitHub Actions、GitHub App、Durable Object、Turnstile 或下载代理业务逻辑。

## 运行与发布边界

- 开发分支：`codex/ui-saas-console`
- 测试 Worker：`docker-offline-builder-preview`
- 生产分支：`main`
- 生产 Worker：`docker-offline-builder`
- 测试环境使用独立 Durable Object 数据空间，避免测试任务进入生产历史。
- 开发阶段先部署测试 Worker，验证完成后再合并到 `main` 并部署生产 Worker。

## 页面设计

### 首页

首页采用控制台布局，包含顶部导航、状态概览、新建任务卡片、当前任务卡片和最近构建摘要。

- 顶部显示产品名称、服务运行状态、构建历史入口。
- 状态概览显示保留周期、当前运行任务和构建能力等简短信息。
- 新建任务卡片保留 Docker 版本下拉加自定义输入、架构选择和 Turnstile。
- 提交按钮在请求期间显示明确状态，并避免重复提交。
- 当前任务卡片显示版本、架构、任务状态、当前步骤、步骤数量和近似百分比进度。
- 构建中提供 GitHub Actions 详情链接；只有成功后显示 Release 下载链接。
- 最近构建摘要显示最近若干任务，并提供历史页入口。

### 历史页

历史页采用任务列表/卡片混合布局，展示近 15 天构建任务。

- 展示版本、架构、创建时间和状态。
- 支持按状态筛选：全部、构建中、成功、失败。
- 构建中的任务显示实时进度和当前步骤。
- 成功任务显示 GitHub 构建链接和下载链接。
- 失败任务显示 GitHub 构建链接和错误信息摘要（若后端提供）。
- 空列表和加载失败状态提供明确提示。

## 视觉与交互

- 使用蓝白作为主色，辅以绿色成功、橙色进行中、红色失败状态色。
- 使用浅色背景、边框和阴影建立控制台层次，保持页面简洁。
- 桌面端使用双栏或主次栏布局，移动端切换为单栏。
- 添加轻量的进度条和状态切换动画；不引入外部前端框架或大型资源。
- 所有来自接口的数据继续经过 HTML 转义，链接使用安全的属性设置。
- 保持现有 favicon、Turnstile 和下载加速前端逻辑。

## 数据与状态流

1. 页面加载时请求历史摘要或历史列表。
2. 提交表单后创建任务并展示任务卡片。
3. 页面按现有轮询机制请求任务状态。
4. `starting`、`queued`、`building` 状态展示进度区域。
5. `success` 状态展示下载入口，`failed`/`expired` 状态恢复提交按钮并展示错误提示。
6. 历史页按现有 API 数据刷新进行中任务，不新增后端存储接口。

## 错误处理与兼容性

- API 请求失败时显示可读错误，不让页面停留在无限加载状态。
- GitHub Actions 状态暂时无法读取时显示“正在同步构建状态”，不误报为失败。
- 保持现有 API 路径和字段兼容，前端仅扩展对已有字段的展示。
- 不把自定义下载代理域名传给 Worker，继续仅在浏览器端处理 Release 下载链接。

## 验证标准

- `npm run check`、`node --check src/worker.js` 和 `git diff --check` 通过。
- 首页在桌面端和窄屏移动端布局正常。
- 任务提交、轮询、失败、成功和下载链接显示流程正常。
- 历史页筛选、进度展示和链接跳转正常。
- 测试 Worker 可独立访问，且不污染生产任务历史。
- 测试确认后再合并到 `main` 并部署生产环境。
